# 🔒 Security Vulnerability Report

Generated by automated code review of the DQN-Autonomous-Vehicle-on-CARLA project.

---

## 🔴 High — Unsafe `pickle.load()` (arbitrary code execution)

**File:** `DQN-Autonomous-Vehicle-on-CARLA/replay.py`

```python
def load(self, file):
    with open(file, "rb") as f:
        self.samples = pickle.load(f)   # ← deserializes untrusted data
```

`pickle.load()` executes arbitrary code embedded in the byte stream. The path is built from the user-supplied `--model` CLI argument (`args.model + self.file` in `__init__`). If a malicious or tampered `.dat` file is loaded, **arbitrary Python code runs** during unpickling.

**Fix options:**
- Replace pickle with a safe format (JSON / `numpy.save` / `tf.train.Checkpoint`).
- Or use `pickle.load` with a restricted `Unpickler` that whitelists only the expected classes (`Sample`, `State`).

---

## 🟠 Medium — Path injection via `--model` argument

**Files:** `rl_car_driver.py`, `replay.py`, `dqn.py`

`args.model` is concatenated directly into filesystem paths without sanitization:

```python
base_output_dir = 'eval-' + args.model          # rl_car_driver.py
self.load(args.model + self.file)               # replay.py
self.target_net.load_weights(args.model)        # dqn.py
shutil.rmtree(base_output_dir, ignore_errors=True)  # rl_car_driver.py
```

A crafted value (e.g. `../../some/dir`) can cause **path traversal** or unintended `rmtree` deletion. Severity is limited because the tool is run by the user themselves, but it's a real footgun in shared/CI environments.

**Fix:** validate `args.model` against an expected pattern (e.g. `run-out-\d{4}-\d{2}-\d{2}-.*`) and resolve paths with `os.path.realpath` + containment check.

## 🟠 Medium — Unpinned / vulnerable dependencies

**File:** `requirements.txt`

```
tensorflow>=2.0,<3.0     # very wide range; many TF 2.x CVEs (Keras, TFLite, tf.keras)
numpy==1.22.0            # known CVEs (e.g. CVE-2021-33430 buffer overflow)
opencv-python            # unpinned; older versions have CVEs
blosc                    # unpinned
traitlets                # unpinned
```

- **TensorFlow** 2.x has a long history of CVEs in `tf.keras`, `tf.linalg`, `tf.raw_ops`. Pinning to a patched 2.x release (e.g. `>=2.13,<2.16`) reduces exposure.
- **numpy 1.22.0** is outdated; upgrade to a patched 1.22.x or 1.26.x.
- **opencv-python** and **blosc** have no version pin → non-reproducible builds and silent CVE drift.

**Fix:** pin exact versions and run `pip-audit` / `safety` in CI.

## 🟡 Low — Deprecated `np.fromstring` (data-integrity risk)

**File:** `DQN-Autonomous-Vehicle-on-CARLA/state.py`

```python
np.fromstring(blosc.decompress(self.screens[i]), dtype=np.uint8)
```

`np.fromstring` is deprecated and emits a `VisibleDeprecationWarning` — which this project *converts to an error* in `rl_car_driver.py` (`warnings.filterwarnings('error', ...)`). So a future numpy bump will **crash training**. Not a security hole per se, but a robustness/availability issue.

**Fix:** use `np.frombuffer(...)`.

## 🟡 Low — Unauthenticated CARLA connection

**Files:** `car/car_carla.py`, `utils/config.py`

```python
client = carla.Client(connection_data["server_ip"], connection_data["server_port"])
```

The CARLA server address comes from `config.json` with no validation or authentication. If `config.json` is attacker-controlled, the client will connect to an arbitrary host/port. Acceptable for a local research tool, but worth noting for multi-tenant setups.

## 🟢 Informational — Other observations

- **`shutil.rmtree`** on a derived path (`rl_car_driver.py`) — destructive; pair with the path-validation fix above.
- **Global mutable state** (`stop`, `train_epsilon`, `State.IMAGE_HEIGHT`) mutated across threads — not a security vuln, but a correctness hazard.
- **No file-permission checks** when writing `config.json` / model checkpoints — fine for local use, risky in shared filesystems.

---

## ✅ Recommended priority order

1. Replace or sandbox `pickle.load()` in `replay.py`.
2. Validate/sanitize `args.model` before using it in paths and `rmtree`.
3. Pin dependencies and run `pip-audit` in CI.
4. Replace `np.fromstring` → `np.frombuffer`.
